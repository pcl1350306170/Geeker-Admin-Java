# 个人开发资产库 V1.0 开发需求说明

## 一、项目背景

当前已有一个基于 Vue3.0 + Java + MySQL 的后台管理系统。

在日常前端开发过程中，会不断积累大量可以重复使用的“开发资产”，例如：

- 以前做过的定制功能
- 可直接复制使用的 JavaScript / TypeScript / Vue / CSS 代码
- Vue3 组件实现
- Sortable.js 等第三方库的使用方案
- 复杂脚本的详细使用步骤
- 项目部署流程
- 开发环境配置
- 开发过程中遇到的问题及解决方案
- 某个客户/项目的特殊定制方案
- 常用 Shell / npm / Git 命令
- CSS / JS / Vue 小技巧
- 项目中经常重复使用的代码片段
- 以前解决过的问题和踩坑记录

目前这些内容主要通过有道云笔记进行记录，但随着内容增加，存在以下问题：

1. 搜索效率低
2. 很难根据模糊记忆找到以前记录的内容
3. 代码复制体验不好
4. 代码和说明混杂，不方便快速复用
5. 无法统计哪些资产经常使用
6. 无法方便地从旧方案复制出一个新的方案继续修改
7. 开发资产没有形成结构化积累

因此，需要在现有 Vue3 + Java + MySQL 系统中增加一个独立的“个人开发资产库”功能。

---

# 二、核心目标

这个系统不是传统意义上的博客，也不是普通后台 CRUD。

核心目标是：

> 将过去开发过程中积累的代码、方案、脚本、踩坑记录等内容沉淀下来，并能够在未来遇到类似需求时，在 10 秒左右完成“搜索 → 找到 → 查看 → 复制 → 复用”。

核心使用流程：

```text
遇到需求
    ↓
打开开发资产库
    ↓
搜索关键词
    ↓
快速找到历史方案
    ↓
查看代码 / 解决方案
    ↓
一键复制
    ↓
用于当前项目
```

系统应该优先保证：

**搜索速度 > 信息定位速度 > 复制速度 > 编辑体验 > 页面视觉效果**

---

# 三、重要技术约束

## 3.1 必须复用现有项目

本需求不是创建一个全新的独立项目。

必须基于当前已有项目进行开发：

```text
现有 Vue3.0 前端
        ↓
现有 Java 后端
        ↓
现有 MySQL
```

禁止因为本需求重新引入：

- Node.js 后端
- Express
- NestJS
- Fastify
- MongoDB
- PostgreSQL
- Redis（除非现有项目已经使用）
- Elasticsearch
- Meilisearch

第一版本只使用现有技术栈。

---

## 3.2 不得破坏现有系统

新增功能必须保证：

- 不影响现有菜单
- 不影响现有路由
- 不影响现有权限
- 不影响现有 API
- 不影响现有业务模块
- 不修改已有数据库表结构，除非确有必要
- 新增数据库表必须使用独立命名空间/统一前缀

建议数据库表统一使用：

```text
dev_asset_
```

作为前缀。

例如：

```text
dev_asset
dev_asset_tag
dev_asset_relation
dev_asset_usage
```

# 六、Solution：定制方案

用于记录以前已经完成过的复杂功能/定制需求。

例如：

```text
Vue3 + Sortable.js 拖拽排序定制方案
```

内容可以包括：

```text
需求背景

实现方案

核心代码

涉及文件

修改步骤

注意事项

后续优化

最终效果
```

这种资产的重点不是单独的一段代码，而是：

> 记录“这个问题以前是怎么解决的”。

---

# 七、Troubleshooting：问题 / 踩坑

用于记录开发过程中遇到的问题以及解决方案。

例如：

```text
标题：
ArkTS @Entry decorated component 只能有一个 root node

问题：

出现的错误信息……

原因：

……

解决方案：

……

注意事项：

……
```

搜索时，错误信息中的关键词也应该能够搜索到该资产。

---

# 八、Procedure：脚本 / 操作流程

用于记录复杂脚本或者操作流程。

例如：

```text
某项目部署脚本使用方法

环境要求：

Node 18+
Java 17+

使用步骤：

1. xxx
2. xxx
3. xxx

配置：

xxx

常见问题：

xxx
```

适合保存：

- 部署流程
- 脚本使用方法
- 环境配置
- 项目初始化
- 打包流程
- 数据库操作流程
- Git 操作流程

---

# 九、Snippet：代码小片段

用于保存非常短的代码。

例如：

```css
多行文字省略：

display: -webkit-box;
-webkit-line-clamp: 2;
-webkit-box-orient: vertical;
overflow: hidden;
```

这种内容应该支持：

**搜索 → 预览 → 一键复制**

不需要复杂的文章结构。

# 十、Asset 数据模型

核心表：

```text
dev_asset
```

建议字段：

```text
id
title
type
description
content
language
tags
is_favorite
usage_count
parent_id
created_by
created_at
updated_by
updated_at
```

字段说明：

### id

资产 ID。

### title

资产名称。

### type

资产类型：

```text
CODE
SOLUTION
TROUBLESHOOTING
PROCEDURE
SNIPPET
```

### description

资产简介。

用于搜索结果中的摘要展示。

### content

资产正文。

建议使用 Markdown 格式保存。

### language

代码语言。

例如：

```text
javascript
typescript
vue
css
scss
html
java
sql
shell
json
arkts
```

非代码类型可以为空。

### tags

资产标签。

如果现有项目方便使用独立标签表，则使用标签关联表。

如果为了第一版开发简单，可以先使用 JSON 字符串保存。

### is_favorite

是否收藏：

```text
0：否
1：是
```

### usage_count

使用次数。

每次点击“复制”时 +1。

### parent_id

来源资产。

用于支持：

> 从旧方案创建新方案。

例如：

```text
Vue3 Sortable 基础方案
        ↓
医疗项目 Sortable 定制
        ↓
PC 项目 Sortable 定制
```

如果当前版本暂时不实现资产继承关系，也需要保留该字段，为后续功能做准备。

# 十四、搜索功能

搜索是整个系统最重要的功能。

## 14.1 搜索范围

至少搜索：

```text
title
description
content
tags
language
```

---

## 14.2 支持模糊搜索

例如资产标题：

```text
Vue3 Sortable 限制拖拽范围
```

用户搜索：

```text
sortable
```

应该可以找到。

搜索：

```text
拖拽
```

也应该可以找到。

搜索：

```text
限制容器
```

也应该可以找到。

---

## 14.3 支持错误信息搜索

例如保存了：

```text
In an @Entry decorated component, the build method can have only one root node
```

以后用户直接搜索：

```text
only one root node
```

或者：

```text
root node
```

也应该可以找到对应资产。

---

## 14.4 搜索结果排序

建议按照以下优先级排序：

```text
标题匹配
>
标签匹配
>
简介匹配
>
正文匹配
>
代码匹配
```

如果实现成本较高，第一版可以统一使用 MySQL 全文搜索。

不要为了第一版引入新的搜索服务器。

# 三十、UI 设计要求

不要直接使用传统后台管理系统的“表格 + 查询 + 新增”风格作为开发资产库首页。

开发资产库应该偏向：

```text

+

+
代码搜索工具
```

视觉上保持：

- 简洁
- 高信息密度
- 快速操作
- 少弹窗
- 少无意义装饰
- 代码展示清晰
- 搜索突出
- 复制按钮明显


# 三十六、权限

第一版直接复用现有系统登录用户。

如果当前系统已经存在用户 ID：

```text
created_by
updated_by
```

直接关联。

第一版不需要重新开发用户系统。

如果当前系统只有单用户，也要保留用户字段，为未来多人使用预留。

---

# 三十七、数据安全

删除采用逻辑删除。

正文保存时需要注意：

- SQL 注入
- XSS
- Markdown HTML 注入
- 非法脚本执行

Markdown 渲染时：

**禁止默认执行用户保存的任意 HTML / JavaScript。**

需要根据现有前端 Markdown 组件能力进行安全过滤。

---

# 四十、开发实施要求

AI 在开始修改代码之前，必须先分析当前项目。

不得直接假设项目结构。

第一阶段：

```text
1. 分析 Vue3 项目结构
2. 分析路由
3. 分析菜单
4. 分析权限
5. 分析 Axios/request 封装
6. 分析现有 UI 组件
7. 分析 Java Controller
8. 分析 Service
9. 分析 Mapper/Repository
10. 分析 MySQL 数据库结构
11. 分析项目命名规范
12. 分析现有分页方式
```

分析完成后，再确定实际代码应该放在哪里。

# 四十一、AI 开发时必须遵守

## 1. 不要重构现有项目

除非为了接入本功能确有必要，否则：

**不要修改现有业务代码。**

---

## 2. 不要修改现有公共组件

如果现有组件已经可以满足需求：

直接复用。

如果无法满足：

优先新增开发资产库自己的组件。

不要为了这个功能大规模修改全局组件。

---

## 3. 遵循现有项目代码规范

包括：

- 文件命名
- API 命名
- Java 包结构
- Controller 风格
- Service 风格
- Mapper 风格
- Vue 组件结构
- SCSS 规范
- ESLint
- TypeScript 类型规范

---

## 4. 不要擅自升级依赖

除非确认现有版本无法实现需求。

不要因为某个新组件方便，就升级：

```text
Vue
Vite
Element Plus
Java
Spring Boot
```

等核心依赖。

# 四十三、验收标准

## 搜索

输入：

```text
sortable
```

能够找到相关 Sortable 资产。

输入：

```text
拖拽
```

能够找到相关资产。

输入错误信息关键词：

```text
root node
```

能够找到对应踩坑记录。

---

## 复制

点击代码块：

```text
复制
```

能够直接复制代码。

复制成功后显示：

```text
复制成功
```

并增加使用次数。

---

## 复用

点击：

```text
基于此资产创建
```

能够复制旧资产内容创建新的资产。

新资产与旧资产保持关联。

---

## 收藏

点击：

```text
收藏
```

资产出现在：

```text
我的收藏
```

---

## 最近使用

查看/复制资产后：

```text
最近使用
```

能够出现该资产。

---

刷新页面后：

```text

收藏

使用次数
```

数据不能丢失。

# 四十四、最终产品核心原则

整个开发资产库必须遵循以下原则：

### 原则 1

**搜索优先。**

### 原则 2

**复制优先。**

### 原则 3

**低记录成本。**

### 原则 4

**代码优先于文章。**

### 原则 5

**历史资产应该能够快速派生新的资产。**

### 原则 6

**不要把系统做成传统博客。**

### 原则 7

**不要把系统做成传统后台 CRUD。**

### 原则 8

**第一版保持简单，不提前引入复杂基础设施。**

# 四十五、最终目标

希望最终形成这样的工作流：

```text
                    日常开发
                       │
                       ↓
                遇到一个新问题
                       │
                       ↓
                Ctrl + K / 打开资产库
                       │
                       ↓
                    搜索
                       │
                       ↓
              找到以前做过的方案
                       │
             ┌─────────┴─────────┐
             ↓                   ↓
          直接复制             基于旧方案创建
             ↓                   ↓
          当前项目             新定制方案
             │                   │
             └─────────┬─────────┘
                       ↓
                    完成开发
                       │
                       ↓
                新方案再次沉淀
                       │
                       ↓
                 我的资产库越来越强
```

最终，这个系统不是一个简单的“笔记软件”，而应该成为个人开发过程中的：

> **第二大脑 + 代码片段库 + 定制方案库 + 踩坑数据库 + 开发经验库。**
